# AIPOL 연금개혁 정책실험 실행 계약

- 문서 상태: 구현 기준 계약 v0.2 (v1 보존, v2 별도 검토)
- 기준일: 2026-08-02
- 적용 이슈: #4, #5, #6, #7
- 공식 사례명: **KAPS Human + AI Collaboration Policy Lab: 연금개혁-AI 숙의민주주의 정책실험**
- 행사: 2026 한국정책학회 하계학술대회 특별기획Ⅰ, 2026-08-12 14:30–16:10(100분)
- 임시 공개 목표 주소: `https://aipol.kaps.or.kr` (HTTPS 200 확인 전에는 미개통)
- 공식 주소 전환 예정: `https://aipol.kaps.or.kr`

이 문서는 행사 화면, 측정 자료, 공개 사이트, AI 서비스와 배포가 같은 기준을 사용하도록 묶는 실행 계약이다.
헌장과 방어장치는 `RFC-0001-framework.md`와 `.agents/context/agents-rules.json`을 따른다.

공식 포스터는 대외 설명의 기준이고, 이 문서의 세 번 측정 절차는 이후 합의된 행사 실행안이다. 실제 행사에 적용하려면
KAPS·연구책임자가 서명한 동결표에서 이 절차가 포스터의 두 평가 구조를 구체화·대체함을 승인해야 한다. 승인 전에는
참가자 수집 기능을 열지 않는다.

## 1. 결정된 범위

### REQ-EXP-001 — 세 번의 측정

참가자의 선택은 다음 세 시점에 각각 제출한다.

1. `M1`: A/B/C 정책안을 먼저 단순 선택
2. `M2`: 개인 조건 비교 뒤 A/B/C를 다시 선택하고 `수용`, `조건부 수용`, `비선택` 의견을 별도 제출
3. `M3`: M2에서 만든 잠정 의견 D, 전문가 논평, 진행자가 선별한 공개 청중 의견, 수정 의견 D′를 모두 확인한 뒤 A/B/C를 최종 선택

각 측정은 `1차`, `2차`, `3차`로 화면에 표시한다. 이전 응답을 덮어쓰거나 세 측정을 합치지 않는다.

### REQ-EXP-002 — 노출 순서

실행 순서는 아래와 같다.

v2 검토 절차는 아래 순서로 고정한다.

`동의·참여코드 → M1 → 개인 조건부 비교(E1a) → M2(선택+의견) → 잠정 의견 D(E2) → 전문가 논평(E1b) → 공개 청중 의견·진행자 선별(A1) → 수정 의견 D′(E3) → M3 → 결과 안내`

기존 운영 절차 v1은 별도 절차 버전과 기존 원장으로 보존한다. v2 검토 링크와 원장은 v1과 섞지 않으며,
별도 검토가 끝나기 전 운영 기본값을 v2로 바꾸지 않는다.

- `E1a`, `E2(D)`, `E1b`, `E3(D′)`는 서로 다른 자료·버전·승인·콘텐츠 해시로 기록한다.
- `A1`은 공개 청중 발언 중 진행자가 선별한 내용만 append-only 공개 입력 원장에 등록한다. 참가자 화면에서 개인 텍스트를 수집하지 않는다.
- 단계 건너뛰기와 미래 단계 자료 미리 보기를 막는다.
- 새로고침·재접속은 마지막으로 완료한 단계부터 이어간다.
- 행사 중 자료를 바꾸지 않는다. 변경하면 새 실험 버전으로 실행한다.
- M1·M2의 개인별 응답과 중간 집계는 M3 제출 전 참가자에게 공개하지 않는다. AI 생성용 집계는 운영자 화면에서만 사용한다.

### REQ-EXP-003 — 해석의 한계

- `M1→M2`는 **개인 조건 비교 뒤 관찰된 개인 내 변화**로 보고한다.
- `M2→M3`는 **D, 전문가 논평, 진행자 선별 공개 청중 의견과 D′를 거친 뒤 관찰된 추가 변화**로 보고한다.
- D와 D′ 및 전문가 논평의 개별 효과는 이 설계만으로 분리해 추정하지 않는다.
- 무작위 배정이나 통제집단 없이 “전문가가 바꿨다”, “AI가 설득했다” 같은 인과 표현을 사용하지 않는다.
- 변화 자체를 숙의의 질 향상이나 더 현명한 선택으로 해석하지 않는다.

### REQ-EXP-004 — 같은 질문과 선택지

- M1·M2·M3의 주 선택 문항, A/B/C 선택지, 응답 척도와 표시 순서를 동일하게 유지한다.
- 각 안은 표시 문자와 분리된 안정적인 `policy_option_id`를 사용하고, 레버 값·출처·승인 버전을 정책안 레지스트리에 동결한다.
- 참가자별 선택지 표시 순서를 한 번 정하면 세 측정에서 그대로 유지하고 그 순서를 기록한다.
- 특정 안을 기본 선택하거나 시각적으로 강조하지 않는다.
- AI가 만든 D/D′안은 M3에서 별도 비교·수용도 문항으로 평가하되, A/B/C 재선택 주 문항은 그대로 유지한다.
- 선택지 추가 효과를 AI 의견 효과와 섞어 보고하지 않는다.

### REQ-EXP-005 — 응답 스냅숏

각 측정은 append-only 스냅숏으로 저장한다.

필수 필드:

- `experiment_version`
- `session_id`, `state_revision`
- `participant_pseudonym`
- `participant_type` (`real`, `synthetic`)
- `measurement_id` (`M1`, `M2`, `M3`)
- `choice`
- `stance` (`M2` v2에서 `accept`, `conditional`, `reject`)
- `reason`(선택 입력)
- `confidence`와 사전 확정된 동일 척도
- `option_set_version`
- `option_order`, `preceding_exposure_hash`
- `submitted_at`(서버 시각)
- `idempotency_key`

보류, 무응답, 중도 이탈도 정상 상태로 보존한다.

서버는 `(experiment_version, session_id, participant_pseudonym, measurement_id)` 복합 고유 제약을 둔다. 측정 제출과
상태 전이는 한 트랜잭션에서 처리하며, 기대 `state_revision`이 다르면 거부한다. 같은 idempotency key와 다른 payload는
충돌로 처리하고, 미래 단계 제출과 이미 제출한 측정의 수정은 서버에서 막는다. 기본 집계는 `participant_type=real`만 포함한다.

### REQ-EXP-006 — 노출 기록

각 자료 노출은 다음 필드로 별도 기록한다.

- `artifact_id`, `artifact_version`, `content_hash`
- `experiment_version`, `session_id`, `participant_pseudonym`, `stage_sequence`
- `opened_at`, `completed_at`, `read_ack`
- `fallback_used`
- 전문가 또는 운영자의 승인 식별자

이 기록은 응답과 연결하되 개인을 직접 식별하는 값은 넣지 않는다.
한 세션의 E2(D)와 E3(D′)는 단계별로 모든 참가자에게 각각 같은 `content_hash`를 사용한다. 두 자료를 같은 행이나
같은 artifact ID로 덮어쓰지 않는다. 장애가 발생하면 세션 전체가 같은 승인 대체본으로 전환하며,
일부 참가자만 다른 자료를 본 경우 별도 분석군으로 분리하고 동일 개입으로 합치지 않는다.

## 2. 개인 조건부 비교 계산

### REQ-CALC-001 — 명칭과 표시

- 서비스는 “AI 예측”이 아니라 **입력 조건과 공개된 가정에 따른 정책안 비교**로 표시한다.
- 결과는 공인 연금액, 개인 재무상담 또는 확정된 미래 수령액처럼 표현하지 않는다.
- 계산식, 기준일, 정책안 버전, 포함·제외 항목과 출처를 결과 화면에서 확인할 수 있어야 한다.

### REQ-CALC-002 — 전달 소스의 사용 경계

외부 기여 개인 연금 시뮬레이터는 화면 흐름과 입력 경험을 참고하되, 하드코딩된 예시 값과 계산식을 행사 정본으로 채택하지 않는다.
세부 근거는 `docs/source-audit-personal-pension-simulator.md`에 기록한다.

그 이유는 다음과 같다.

- 실제 전문가 A/B/C 정책값과 다르다.
- 현재 나이 입력이 계산에 쓰이지 않는다.
- 소득구간 세율, 국고 환산율과 개인 보험료를 합쳐 실제 개인부담처럼 보일 수 있다.
- 정책값과 정량 설명의 출처·기준일이 없다.
- `AI POLICY EXPLAINER`는 AI 호출이 아니라 고정 문장이다.

정책안·산식은 연금 도메인 검토자와 전문가 승인 후 별도 버전으로 동결한다.

### REQ-CALC-003 — 소득·인구 데이터의 사실 표시

- 제공된 개인 시뮬레이터에는 NVIDIA 데이터, 페르소나, 인구통계 가중, 소득분포가 없다.
- 공개된 100명 사전 실행은 `nvidia/Nemotron-Personas-Korea` v1.0 합성 페르소나에서
  행정안전부 2026년 5월 31일 주민등록 연령 구성에 맞춰 선택한 표본이다. 행정자료는 연령 구성에만 사용했다.
- 이 100명 실행에는 실증 소득분포 가중을 적용하지 않았고, 원본 페르소나에 개인 소득 수치 필드도
  없으므로 실제 개인 소득이나 보험료를 계산한 결과로 해석하지 않는다.
- 합성 표본은 파이프라인과 부하 시험에만 사용하며 시민 의견이나 정책 효과의 근거로 사용하지 않는다.

### REQ-CALC-004 — 계산 검증

- 계산 로직은 UI와 분리된 순수 함수 또는 독립 서비스로 구현한다.
- 정책 설정에는 `source`, `as_of`, `version`, `approved_by`를 필수로 둔다.
- 전문가가 승인한 기준 사례(golden fixture), 경계값, 잘못된 입력, 관계 제약을 자동 시험한다.
- 화면 결과와 독립 재계산 결과가 일치해야 한다.

## 3. 전문가·AI 자료

### REQ-CONTENT-001 — 전문가 설명

전문가 설명에는 작성자, 소속, 검토일, 버전, 근거와 승인 상태를 표시한다. 익명 하드코딩 문장을 전문가 설명으로 부르지 않는다.

### REQ-CONTENT-002 — 잠정 의견 D와 수정 의견 D′

- D는 M2 마감 뒤 승인된 집계와 비공개 의견 지문을 근거로 생성한다.
- D′는 D 노출, 승인된 전문가 논평, 진행자가 선별·등록한 공개 청중 의견이 모두 고정된 뒤 별도로 생성한다.
- D와 D′는 서로 다른 모델 provenance·근거 해시·사람 승인·공개 기록을 가진다. 사람 승인이 끝난 동일본만 모든 참가자에게 노출한다.
- 모델, 버전, 프롬프트 버전, 생성일, 근거, 사람 승인과 콘텐츠 해시를 기록한다.
- 실시간 생성·승인이 제한시간 안에 끝나지 않으면 세션 전체를 행사 전에 승인한 고정 대체본으로 전환한다.
- AI 우월성, 합의 달성, 시민 설득을 주장하지 않는다.
- 기존 시나리오 중 최종 사용 범위는 콘텐츠 동결표에서 확정한다. 미확정 자료는 화면에 노출하지 않는다.

### REQ-CONTENT-003 — 사람 승인 게이트

전문가 설명과 AI 자료는 `human_gate` 승인 없이는 참가자 화면에 공개하지 않는다. 승인 뒤 내용이 바뀌면 기존 승인은 무효다.

## 4. 개인정보와 연구 데이터

### REQ-PRIV-001 — 최소 수집

- 이름, 이메일, 전화번호, 원시 IP를 연구 응답에 저장하지 않는다.
- 참여자 식별은 무작위 가명 ID를 사용한다.
- 개인 계산 원값은 기본적으로 브라우저 안에서만 사용한다.
- 연구에 필요한 경우에도 동의를 받은 구간값만 별도 전송한다.
- 동의문 버전, 동의 시각과 철회 상태를 저장하되 신원정보와 연구 응답을 직접 연결하지 않는다.

### REQ-PRIV-002 — 고지의 정확성

개인 계산 입력과 투표 응답의 저장 여부를 분리해 고지한다. 투표를 저장하면서 “입력정보는 저장되지 않습니다”라고 포괄적으로 표시하지 않는다.

### REQ-PRIV-003 — 동결 전 필수 결정

보존기간, 삭제 절차, 관리자 접근 권한, 연구윤리 승인 범위와 국외 이전 여부는 운영 동결 전에 사람이 확정한다. 확정되지 않으면 실제 참가자 수집을 열지 않는다.
Azure·CDN·WAF·오류 추적·분석 도구·관리자 감사 로그별 IP와 입력값 수집 여부, 마스킹, 보존기간도 동결표에 포함한다.
소규모 세그먼트 공개는 사전 확정한 최소 셀 크기 미만을 억제하거나 상위 구간으로 합친다.

## 5. 공개 사이트와 브랜드

### REQ-WEB-001 — 주체와 명칭

- KAPS와 공식 정책실험을 전면에 둔다.
- 헤더 기본 조합은 `한국정책학회 공식 로고 | AIPOL`이다.
- 보조명은 `KAPS Human + AI Collaboration Policy Lab`이다.
- Nextain은 승인된 역할 문구와 함께 하단의 작은 기술 구현 크레딧으로만 표시한다.
- OpenAI가 주최·제공한 서비스로 오해할 이름과 시각 요소를 사용하지 않는다.

### REQ-WEB-002 — 디자인

- 연한 청회색 배경, 흰 카드, 짙은 남색 글자, 파란 주요 동작의 차분한 공공서비스 인상을 사용한다.
- KAPS 자홍색은 학회 식별용 보조 강조색으로 제한한다.
- 로봇·두뇌·네온보다 근거, 단계, 표와 대화 구조를 시각화한다.
- 특정 정책안을 더 밝거나 우월하게 표시하지 않는다.

`aipol.kaps.or.kr` 연결 전에는 존재하지 않는 주소를 canonical로 쓰지 않는다.
영어 경로는 번역된 title·description과 `og:locale=en_US`를 사용하고 한국어 경로를 alternate로 연결한다.

### REQ-WEB-004 — 공식 도메인 전환

`aipol.kaps.or.kr`이 실제 서비스되면 다음을 한 배포에서 함께 바꾼다. Azure Static Web Apps만으로 호스트별 같은 경로
301을 보장할 수 없으면 Azure Front Door 또는 기존 DNS 제공자의 redirect 서비스를 임시 호스트 앞에 둔다.

1. `aipol.kaps.or.kr/*`를 같은 경로의 `aipol.kaps.or.kr/*`로 301 이동
2. canonical, `og:url`, sitemap을 공식 주소로 전환
3. 두 호스트의 인증서와 주요 경로 확인

### REQ-WEB-005 — 공유 이미지와 아이콘

- OG 이미지는 1200×630 sRGB PNG이며 1MB 이하를 목표로 한다.
- OG에는 KAPS, AIPOL, 공식 사례명과 세 번의 측정 구조를 담는다.
- `og:image:alt`를 제공한다.
- `favicon.svg`, 16/32/48px를 포함한 favicon, 180×180 apple-touch-icon을 제공한다.
- 미리보기와 관리자 화면은 `noindex, nofollow`로 둔다.

## 6. AI 정책동향·챗봇·통합 관리자

출시 단위는 서로 독립한다.

| 출시 단위 | 현재 범위 | 운영 전 필수 게이트 |
|---|---|---|
| `public-site` | AIPOL 소개·행사·방법·메타데이터 | 정적 사이트·메타·접근성 시험 |
| `experiment-service` | v1 보존 + v2 M1·E1a·M2·D·E1b·A1·D′·M3 | 정책안·산식·콘텐츠·개인정보 동결과 전체 E2E |
| `policy-news` | 해외 정책 원문 수집·검수 | 출처 허용목록·저작권·비용·승인 흐름 |
| `chatbot-beta` | 승인 지식 기반 질의응답 | 고정 평가·근거·기권·보안 기준 |
| `admin` | 지식·행사 자료·평가 관리 | 역할표·다중인증·감사로그·권한 분리 |

한 출시 단위의 완료를 전체 AIPOL 완료로 보고하지 않는다. `public-site`는 참가자 입력·투표·챗봇·관리자 기능을 포함하지 않는다.

### REQ-AI-001 — 정책동향 수집

- 기존 `bots/policy_news` 구현을 출발점으로 사용한다.
- 공식 원문, 원문 보존, 수집시각, 정책 상태를 먼저 기록한다.
- Azure AI Foundry의 번역·요약·분류는 검수 대기 초안만 만든다.
- `naia-kb-compiler`는 포트/어댑터로 연결하고 AIPOL이 엔진 내부에 종속되지 않게 한다.
- 승인된 항목만 공개한다.
- Foundry 어댑터는 입력/출력 JSON Schema, 원문 식별자, 재시도·중복키, 모델·지역·할당량, 실행별 비용과 kill switch를 정의한 뒤 연결한다.

### REQ-AI-002 — 근거형 챗봇

- 챗봇은 승인된 지식만 검색하고 문장별 근거 구간과 원문 링크를 제시한다.
- 근거가 부족하면 답을 만들지 않고 검색 결과 또는 부족 안내를 제공한다.
- 실험 참여 정보와 투표 데이터에 접근하지 않는다.
- 고정 평가 세트, 프롬프트 삽입 방어, 속도 제한을 통과한 뒤 별도 베타로 공개한다.
- 답변 스키마, 인용 근거 일치 판정, 근거 부족 시 기권 기준과 평가 통과선을 별도 챗봇 계약에 수치로 고정한다.

### REQ-AI-003 — 통합 관리자

관리자는 공개 KAPS 사이트와 인증 경계를 분리한다. 최소 기능은 다음과 같다.

- 원문 출처와 수집 작업 상태
- 지식 항목 검토·승인·반려·버전 이력
- 전문가·AI 행사 자료 승인과 해시 확인
- 챗봇 설정·평가·근거 없는 답변 검토
- 감사 로그와 역할 기반 접근

관리자 계약에는 역할별 권한표, 편집자와 승인자의 분리, 다중인증, 세션 만료, 감사 로그 변경 방지를 포함한다.

공개 메뉴와 sitemap에는 관리자 주소를 노출하지 않는다.

## 7. Azure와 배포

### REQ-OPS-001 — 리소스 그룹

- 개발: `rg-aipol-dev`
- 운영: `rg-aipol-prod`
- AIPOL 자원은 기존 Nextain 공용 리소스 그룹과 분리한다.
- 기본 지역은 Korea Central을 우선하되, 서비스 가용 지역 제약은 배포 정의에 명시한다.

### REQ-OPS-002 — 환경 분리

개발·운영은 별도 이름, 비밀, 데이터 저장소, 로그와 비용 태그를 사용한다. 실제 참가자 데이터는 운영 환경에만 저장한다.

### REQ-OPS-003 — 배포 게이트

각 출시 단위 배포 전 그 단위에 해당하는 다음 항목을 모두 통과한다. 정적 `public-site` 배포 성공은 참가자 수집을 허가하지 않는다.

- 빌드, 단위 시험, 세 측정 전체 E2E
- 메타데이터·OG·robots·sitemap 시험
- 개인정보 네트워크 시험
- 접근성·모바일 시험
- Azure 사전 검증과 상태 확인
- 독립 적대 검토의 P0/P1/P2 미처리 0건
- 비밀 스캔, 비용 경보, rollback·백업·복구 리허설
- 서명된 동결표와 기본 `collection_enabled=false` 확인(`experiment-service`만)

GitHub Actions는 기본 대상을 `dev`로 두고 시험 작업이 성공해야 배포 작업이 실행되게 한다. 운영은 보호된
`aipol-prod` environment의 사람 승인을 추가로 요구한다.

### REQ-OPS-004 — 100분 진행 시간

운영 리허설의 기준 시간은 다음과 같다.

| 구간 | 누적 시간 | 생략 가능 여부 |
|---|---:|---|
| 오프닝·동의·참여 연결 | 0–10분 | 동의·연결 확인 생략 불가 |
| M1·개인 조건부 비교·M2 | 10–35분 | 세 단계 모두 생략 불가 |
| M2 집계·D 생성·사람 승인 | 35–50분 | 시간 초과 시 승인 고정 대체본 |
| D·전문가 논평·공개 청중 의견·진행자 선별 | 50–70분 | 논평 분량만 축약 가능 |
| D′ 생성·사람 승인·M3 | 70–85분 | 시간 초과 시 승인 고정 대체본, M3 생략 불가 |
| 결과·한계 안내 | 85–95분 | 중간 결과 공개 없이 최종에만 공개 |
| 마감·장애 여유 | 95–100분 | 5분 여유 유지 |

전 구간 리허설에서 95분 안에 핵심 절차가 끝나지 않으면 설명 분량을 줄이지 측정 단계를 삭제하지 않는다.

자동 가상 시계 검증과 장애·복구 증거는 `docs/aipol-virtual-clock-rehearsal-evidence.md`에 기록한다.
이는 실제 참가자·장비를 사용한 95분 현장 리허설을 대체하지 않으며, 현장 리허설은 외부 운영 승인
게이트로 유지한다.

## 8. 검증 계약

### REQ-TEST-001 — 세 측정 무결성

자동 시험은 M1 고정 → E1a 완료 → M2 고정 → D 공개 → 전문가 논평 → 공개 청중 의견 확인·진행자 선별 입력 → D′ 공개 → M3 고정의 순서를 검증한다.
M1 전 E1a, E1a 전 M2, M2 마감 전 D, D·전문가 논평·진행자 선별 공개 청중 의견 전 D′를 막고,
건너뛰기·중복 제출·뒤로가기를 통한 수정·동시 제출·다른 기기 재접속을 시험한다.
세 측정의 `policy_option_id`, 문항, 척도와 참가자별 표시 순서가 같은지도 확인한다.

### REQ-TEST-002 — 재현과 집계

원자료에서 M1→M2, M2→M3, M1→M3 전이표를 독립 재계산하고 화면 집계와 비교한다. 등록자, E1a 완료자,
각 노출 완료자, 각 측정 제출자와 paired sample 분모를 각각 보고하며 무응답과 이탈을 숨기지 않는다.

### REQ-TEST-003 — 개인정보 네트워크 시험

브라우저 요청을 가로채 개인 소득 등 원값이 외부로 나가지 않고, 동의한 연구 필드만 전송되는지 검증한다.
별도로 edge·서버·오류 추적 로그와 관리자 내보내기의 재식별 가능성을 감사한다.

### REQ-TEST-004 — 사용성과 장애 시험

360×800, 390×844, 768px, 1280px 이상에서 키보드, 200% 확대, 동작 줄이기, 44×44px 터치 영역을 확인한다. 느린 네트워크, 저장 실패, 재접속, AI 대체본을 시험한다.

### REQ-TEST-005 — 독립 검토

구현자와 분리된 검토자가 다음 세 관점으로 검토한다.

1. 연구설계: 노출-측정 순서, 문항 동일성, 프레이밍과 인과 문구
2. 연금 도메인: 정책값, 산식, 근거, 기준일, 전문가 승인
3. 개인정보·운영·접근성: 재식별, 중복, 장애, 공유기기, 접근성

완료 기준은 P0/P1/P2 미처리 0건이며, 독립 검토 2회 연속 신규 중대 발견이 없어야 한다.

## 9. 동결 전 사람이 확정할 항목

아래 항목은 추측해 구현하지 않는다.

- 전문가 A/B/C의 최종 숫자·원문·작성자 승인
- 개인 조건부 비교의 최종 산식과 기준 사례
- E2에 포함할 기존 AI 시나리오의 정확한 범위와 D안 처리
- 동일 측정 문항·척도·응답 필수 여부
- 개인정보 보존기간·삭제·연구윤리 승인
- 제공 소스의 재사용 라이선스 또는 권리자의 명시적 허락
- KAPS 공식 로고 원본의 웹 사용 승인과 결합 규정
- 공식 포스터 대비 세 번 측정 절차의 KAPS·연구책임자 승인

이 항목은 서명된 동결표에 승인자·승인일·버전·해시를 기록해야 운영 모드로 전환할 수 있다. 동결표가 없거나
기계 검증에 실패하면 `collection_enabled=false`를 유지한다.
