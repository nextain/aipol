# AIPOL 연금개혁 숙의실험 실행 계약

- 문서 상태: 구현 기준 계약 v4.0
- 확정일: 2026-08-09
- 결정 원천: 2026-08-08 22:00 온라인 논의와 2026-08-09 보충 결정
- 적용 이슈: `nextain/aipol#7`
- 행사: 2026 한국정책학회 하계학술대회 특별기획Ⅰ, 2026-08-12 14:30–16:10
- 공식 공개 포털: `https://aipol.kaps.or.kr/`
- 실제 서비스: `https://session.aipol.kaps.or.kr/cases/pension/experiment/`

이 문서는 연금개혁 숙의실험 v4의 정본 계약이다. 참가자 화면, 어드민, API,
데이터 원장, 프로세스 리뷰와 배포는 이 계약을 함께 따라야 한다.
`RFC-0001-framework.md`와 `.agents/context/agents-rules.json`의 방어장치는 계속 적용한다.

## 1. 정본과 격리 경계

- v4에서 개인 연금 계산, 개인 영향 비교, 예상 연금액 산출 단계는 제거한다.
- M1·M2·M3의 주 선택지는 모두 A/B/C뿐이다. D는 네 번째 선택지가 아니다.
- 쟁점은 참가자의 관심도 직접 선택으로 만들지 않는다.
- 별도 Vercel 리뷰 앱은 사용하지 않는다. 리뷰 페이지는 실제 행사 서비스 안의
  `/cases/pension/experiment/?review=process&dataset=pension-v4-20260808-r1`에서 제공한다.
- 리뷰 파라미터는 `AIPOL_PROCESS_REVIEW_DB_PATH`로 지정한 격리된 append-only 목업 DB
  스냅숏만 읽는다. 참가자·투표 원장과 DB 파일을 분리하고, 목업 여부·콘텐츠 해시·
  저장 시각을 화면에 명시한다.
- v1~v3 코드와 `integrations/kaps-pension-experiment/vendor/`의 두 차례 투표 산출물은
  재현과 감사 목적의 과거 자료일 뿐, v4 활성 경로·계약·배포의 근거가 아니다.
- 2026-08-09 이전의 잘못된 v4 작업은 로컬 격리 브랜치
  `quarantine/pension-v4-drift-20260809`의 커밋 `15bf0c7`에 보존한다. 해당 커밋은
  전체 병합하지 않고, 새 계약과 대조해 필요한 조각만 이식한다.

## 2. 고정된 10단계 절차

1. 동의, 참여 안내와 최소 인구통계 구간 입력
2. A/B/C 전문가 자료 확인과 1차 숙의
3. M1: A/B/C 선택, 선택안 수용 여부, 의견 제출
4. M1 결과와 정확히 5개 핵심 쟁점 확인
5. 전문가의 5개 쟁점 설명과 2차 숙의
6. M2: A/B/C 재선택, 선택안 수용 여부, 의견 제출
7. 두 숙의와 M1·M2를 바탕으로 한 3-AI 협의 D안 생성 및 사람 승인
8. 전문가의 D안·AI 협의 요약·차이·한계 설명과 질의응답
9. M3: A/B/C 재투표와 별도 D안 수용성·의견 제출
10. 최종 결과와 전문가 논평

서버 단계 식별자는 다음처럼 고정한다.

`consent → E0 → M1 → E1a → M2 → E2 → E1b → M3 → complete`

`E0`는 인구통계와 첫 숙의를 포함한 최초 노출, `E1a`는 5개 쟁점과 두 번째 숙의,
`E2`는 사람 승인된 D안, `E1b`는 전문가의 D안 설명이다. 화면은 위 10개 의미 단계를
명확히 보여주되 서버의 append-only 전이와 모순되어서는 안 된다.

## 3. 투표 계약

- M1·M2·M3의 A/B/C 식별자와 표시 순서를 유지하고 기본 선택이나 시각적 우위를 두지 않는다.
- 각 측정은 `choice`, 선택안의 `stance`, 자유 의견, 확신도, 노출 해시, 서버 시각과
  멱등성 키를 append-only 스냅숏으로 저장한다.
- M3의 D 응답은 `d_acceptability`와 `d_opinion`으로 분리한다. D를 `choice`에 저장하지 않는다.
- 이전 응답을 덮어쓰지 않고 미래 단계 제출을 막는다. 재접속은 마지막 완료 단계에서 재개한다.
- 실제 집계의 기본 대상은 `participant_type=real`이며, 합성·리뷰 데이터와 섞지 않는다.

## 4. 숙의와 5개 쟁점

- 각 투표 전에 진행자·전문가가 숙의를 진행한다.
- 녹음 또는 기록은 필요하면 AI로 요약할 수 있으나, 사람 검수가 끝난 요약만 어드민에
  입력·승인한다. 원본 녹음과 미검수 전사문은 D 입력으로 사용하지 않는다.
- 5개 쟁점은 실제 M1 의견 스냅숏을 AI가 쟁점별로 분류한 결과다. 각 수치는 같은 의견을
  중복 계산하지 않은 고유 참가자 수여야 한다.
- 쟁점 자료에는 실제 M1 집계 해시, 분류 근거, 쟁점별 의견 수, 사람 검수자와 승인 시각을
  기록한다. 정확히 5개이며 승인 전 참가자에게 노출하지 않는다.
- 참가자에게 별도의 관심 쟁점 선택 문항을 제공하지 않는다.

## 5. D안과 3-AI 협의

D안 생성 입력은 다음 승인 스냅숏으로 제한한다.

- 동결된 정책안 A/B/C와 정책·재정 제약 자료
- 실제 M1·M2 집계와 각각의 콘텐츠 해시
- 사람 검수를 마친 1차·2차 숙의 요약과 각각의 콘텐츠 해시
- 승인된 5개 쟁점 자료

3개 AI는 서로 구분되는 제안·검토·수정 역할의 기록을 남긴다. 모델·버전, 입력 해시,
검토 가능한 협의 요약, 한계, 생성 시각을 기록하되 숨은 사고과정은 저장하거나 공개하지 않는다.
사람 검수자가 최종 D안을 승인한 뒤에만 참가자에게 동일한 콘텐츠 해시를 노출한다.
행사 시간 안에 생성·검수가 끝나지 않으면 세션 전체를 사전 승인 고정 대체본으로 전환한다.

## 6. 어드민과 동결 게이트

v4 실제 수집을 열기 전에 다음 여섯 범주의 정본 문서와 승인이 모두 있어야 한다.

1. 연구 동의와 개인정보 처리
2. A/B/C 정책안과 출처
3. 전문가 설명 자료
4. 숙의 기록·요약·사람 검수 절차
5. 5개 쟁점 분류·집계 규칙
6. D안 3-AI 협의·사람 승인·고정 대체본 절차

개인 계산식·계산 영수증은 v4 동결 범주가 아니다. 승인 뒤 본문이나 입력 해시가 바뀌면
기존 승인을 무효화한다. 수집 스위치는 위 게이트와 운영 준비 검증을 통과한 뒤에만 연다.

### 6.1 실제 AI 실행과 승인 API

- `POST /api/admin/aipol/experiments/{id}/v4-issue-classification/run`은 서버가 현재 M1
  원장을 읽고 AI 분류를 실행한다. 서버가 모든 고유 M1 참가자를 정확히 한 쟁점에 배정했는지
  검증하고 쟁점별 의견 수를 직접 계산한다.
- `POST /api/admin/aipol/experiments/{id}/v4-issue-classification/approve`는 저장된 실행 ID와
  실행 해시를 참조해야 한다. 클라이언트가 임의로 붙여 넣은 쟁점 JSON은 승인할 수 없다.
- `POST /api/admin/aipol/experiments/{id}/v4-council/run`은 현재 M1·M2 의견 원장, 두 사람
  검수 숙의 요약, 승인된 5개 쟁점과 각 입력 해시를 서버에서 스냅숏한 뒤 서로 다른 세 회사의
  AI를 제안→독립 상호검토→최종 수정 순서로 호출한다.
- `POST /api/admin/aipol/experiments/{id}/v4-council/approve`는 저장된 협의 실행 ID와 현재
  입력 해시가 일치할 때만 사람 승인을 허용한다. 클라이언트가 만든 D안이나 AI 이력 JSON은
  승인할 수 없다.
- 두 실행 원장과 세 협의 단계 원장은 append-only다. 모델·공급자·프롬프트 버전·입력/출력
  해시·생성 시각·실행자·승인자를 남기고, API 응답과 참가자 화면에는 키나 숨은 사고과정을
  노출하지 않는다.

## 7. 개인정보와 공개 결과

- 이름, 이메일, 전화번호와 원시 IP를 연구 응답에 저장하지 않는다.
- 무작위 가명 ID와 동의한 인구통계 구간만 사용한다.
- 원문 의견과 숙의 기록은 공개하지 않고 승인된 집계·요약만 노출한다.
- 보존기간, 삭제 절차, 관리자 권한, 연구윤리 범위와 서비스별 로그 정책을 실제 운영 전에 동결한다.
- 공개 결과는 코호트, cutoff, 분모·기권·이탈 규칙, 집계 버전과 콘텐츠 해시를 고정한다.
- M1→M2와 M2→M3 변화는 순차 숙의 뒤의 관찰 변화일 뿐, AI나 전문가의 단독 인과효과로 표현하지 않는다.

## 8. 리뷰와 배포

- 프로세스 리뷰는 실제 `event-tool` 서비스의
  `/cases/pension/experiment/?review=process&dataset=pension-v4-20260808-r1`을 사용한다.
- 리뷰 페이지는 10단계, 목업 입력 데이터와 승인 게이트를 설명하는 읽기 전용·`noindex`
  화면이며 명시적 개발 플래그가 없으면 API가 열리지 않는다.
- 첫 검토는 격리 개발 서비스와 결정론적 합성 데이터만 사용하며 실제 수집을 끈다.
- 사용자가 프로세스를 승인한 뒤 같은 서비스의 어드민과 참가자 API를 연결한 실제 동작을 검토한다.
- 개발 검증과 실제 운영 배포는 별도 승인 단계다. 개발 리뷰 완료를 운영 수집 승인으로 해석하지 않는다.

## 9. 수용 기준

- v4 참가자 경로와 어드민에서 개인 연금 계산·개인 영향 단계가 보이지 않는다.
- 5개 쟁점은 실제 M1 의견 집계 해시와 사람 승인을 필수로 한다.
- D안은 M1·M2 집계, 두 숙의 검수본, 3-AI 기록과 사람 승인이 없으면 공개되지 않는다.
- M3의 A/B/C 선택과 D 수용성·의견이 별도 필드로 저장된다.
- 프로세스 리뷰, 어드민, 참가자 화면이 별도 리뷰 앱이 아닌 동일 서비스 빌드에서 제공된다.
- 도메인, API, 데이터 원장, 브라우저 흐름과 전체 회귀 테스트가 통과해야 한다.
- 격리 개발 URL의 상태·보안·수집 비활성화를 확인한 뒤에만 리뷰어에게 전달한다.
