# AIPOL 저장소 경계와 공동연구 참여 안내

이 문서는 한국 정책 연구자가 “어느 저장소를 보고 무엇을 기여해야 하는가”를 빠르게 판단하도록 만든 안내서다.

## 1분 결론

| 저장소·서비스 | 역할 | 공개 여부 | 현재 사용 |
|---|---|---|---|
| `nextain/aipol` | 방법론, 도메인 중립 코드, 공개 사이트, 공개 가능한 문서·집계 | 공개 | **공개 정본** |
| `nextain/aipol-lab` | 실제 연금 행사 앱, 운영 절차, 수신 원문, 내부 분석, 원시 증거 | 비공개 | **연구·운영 정본** |
| `nextain/pension-policy-lab` | 2026-08-13 이전 앱 이력 | 비공개 | 읽기 전용 레거시 |
| `armybonita/Pension-Policy-Lab-` | 외부·과거 프로토타입 이력 | 소유자 정책에 따름 | 변경·배포 금지 |
| `aipol.kaps.or.kr` | 공개 소개·방법·사례 | 공개 웹 | 공개 포털 |
| `session.aipol.kaps.or.kr` | 참가·운영·결과 실행 앱 | 제한된 운영 웹 | `aipol-lab` 앱 배포본 |

저장소 이름이 비슷해도 `aipol-labs`, `naia/aipol-labs` 같은 이름을 새 정본으로 만들거나 안내하지 않는다.

## 무엇을 공개 저장소에 넣을 수 있나

공개 가능:

- 다른 정책 분야에도 재사용할 수 있는 프로토콜·방어장치·코드
- 공식 출처와 기준일을 확인할 수 있는 근거
- 개인정보·토큰·내부 주소를 제거한 재현 방법과 집계 성능 결과
- 합성 데이터임이 명확한 예제
- 공개 승인을 받은 사례 설명과 결과

비공개 유지:

- 실제 참가자 원시 응답, 자유서술, 토큰, 기기·접속 로그
- 수신 원문, 회의록, 내부 논의, 미공개 정책안과 보고서 초안
- 운영자 계정, API 키, Discord 토큰, DB 접속정보, 내부 IP
- 공개 승인 전 결과와 작은 집단을 식별할 수 있는 교차표
- 상세 부하시험 원시 로그와 복구 백업

애매하면 공개하지 않고 `aipol-lab`에서 검토한다. 파일에서 민감정보를 지운 것만으로는 충분하지
않다. Git 과거 이력과 파생 결과로 재식별 가능한지도 확인한 뒤 사람이 공개를 승인해야 한다.

## 정책 연구자가 기여하기 좋은 일

- 정책 대안의 공식 근거·기준일·용어 검증
- AI가 합의·여론·정책효과를 과장하는 문장 탐지
- 비참여자·미래세대·소수집단 관점이 빠졌는지 검토
- 측정 지표와 설문 문항이 원래 연구질문에 맞는지 검토
- 작은 집단 공개 기준과 결과 해석의 한계 점검
- 새 정책 도메인의 레버·고정변수·근거 명세 제안
- 고령자·모바일 참가자의 접근성 검토

코드를 몰라도 공식 근거 확인, 용어 교정, 연구설계의 반례 제시는 핵심 기여다.

## Codex와 Claude 사용 기준

### 공통 시작

1. 저장소 루트에서 AI 도구를 연다.
2. `AGENTS.md`를 먼저 읽게 한다. Claude에서는 동일 미러인 `CLAUDE.md`를 사용할 수 있다.
3. 공개 결과물인지 비공개 검토인지 명시한다.
4. “근거 없는 숫자를 만들지 말 것”, “합성을 실제 여론으로 표현하지 말 것”, “남은 한계를 적을 것”을 요청한다.
5. 사람이 diff, 출처, 시험 결과와 공개 경계를 확인한 뒤 PR을 낸다.

### 권장 역할

- **Codex:** 코드·테스트·반복 검증·저장소 변경처럼 실행 증거가 필요한 작업
- **Claude:** 긴 정책 문서의 논리·표현·누락 관점 검토와 적대 리뷰
- **둘 다:** 최종 판단자가 아니다. 공개·정책·연구윤리 결정은 사람이 승인한다.

장기 공동연구나 운영 작업에는 [`naia-adk`](https://github.com/nextain/naia-adk)를 권장한다.
요청→범위→근거→검증→보고를 같은 구조로 남겨 Codex와 Claude 사이의 작업 이관과 재검토를
쉽게 하기 때문이다. 단순 문서 열람이나 작은 오탈자 수정에는 필수가 아니다.

## 처음 참여할 때의 안전한 예시

```text
AGENTS.md와 CONTRIBUTING.md를 읽어 주세요.
이 작업은 nextain/aipol 공개 저장소용입니다.
연금 사례 문서의 공식 출처·기준일·과장 표현을 검토하고,
실제 참가자 데이터나 비공개 운영정보는 사용하지 마세요.
수정안, 근거, 확인 방법, 남은 한계를 함께 제시해 주세요.
```

운영 앱을 고치는 경우에는 공개 저장소가 아니라 `nextain/aipol-lab:apps/pension-policy-lab/`을
사용한다고 명시한다. 레거시 저장소의 코드를 고치거나 그곳에서 배포하지 않는다.

## 적대적 점검: 참여자가 실제로 막히는 지점

- 공개 README만 보면 `event-tool`과 현재 운영 연금 앱을 같은 것으로 오해하기 쉽다. 운영 앱은 비공개 정본임을 먼저 확인해야 한다.
- 과거 문서의 저장소명과 배포 구조는 당시 기록일 수 있다. 문서 첫머리의 “역사 기록” 표지와 현행 운영 문서를 우선한다.
- 공개 코드만으로 실제 행사를 그대로 재현할 수는 없다. 개인정보·운영·수신자료를 의도적으로 제외했기 때문이다.
- 공개 이슈에 내부 자료를 붙이면 사후 삭제로 해결되지 않는다. 공개 전 비공개 저장소에서 먼저 분류한다.
- AI가 만든 매끄러운 요약은 출처 검증을 대신하지 않는다. 공식 원문, 기준일, 코드와 시험 증거를 각각 확인한다.
