# Policy Lab 대외 사이트 디자인

- 상태: 디자인 v2 — 적대 리뷰 반영
- 작성일: 2026-07-21
- 기획 정본: `docs/public-site-plan.md` v2
- 선택 방향: **연구 편집실(Research Editorial Desk)**

## 1. 디자인 목표

사이트는 “AI가 답을 내는 미래형 서비스”가 아니라 **여러 관점과 근거를 펼쳐 놓고 사람이 검토하는
공개 연구 편집실**처럼 보여야 한다.

방문자가 처음 느껴야 할 순서는 다음과 같다.

1. 공공 연구에 필요한 차분함과 신뢰
2. 오픈소스 프로젝트의 투명성과 작동 가능성
3. AI 기술의 존재

AI의 시각적 과장, 연금 숫자 중심의 그래프, 관공서 템플릿, 스타트업 랜딩페이지의 과도한 그라데이션을
피한다.

## 2. 비교한 방향

### A. 연구 편집실 — 선택

- 따뜻한 종이 배경, 짙은 청록 잉크, 주홍색 검토 표시
- 문서 여백, 주석, 연결선, 상태 도장을 시각 언어로 사용
- 사람의 판단과 남은 질문을 중심에 둠
- 연구자·공공기관·시민·개발자 모두에게 읽히는 편집형 구조

### B. AI 관제실 — 제외

- 어두운 배경, 네온 선, 실시간 수치 패널
- 기술 역량은 강하게 보이나 AI가 주체로 오인되기 쉬움
- 첫 실증의 연금 수치가 프로젝트 전체 정체성을 덮을 위험
- 고령 청중과 긴 연구 문서의 가독성에 불리함

## 3. 시각 원리

### 펼쳐 놓기

한 가지 결론을 크게 선전하기보다 `입력 → 관점 → 검토 → 사람 승인 → 남은 한계`를 나란히 보여준다.

### 상태를 숨기지 않기

`구현됨`, `설계 원칙`, `2026.08.12 예정`, `후속 과제`, `가상 시민 검증`을 색뿐 아니라 글자로
표시한다. 색을 보지 못해도 상태가 구분되어야 한다.

### 사람의 결정점을 표시하기

흐름도에서 AI 단계는 사각형, 사람의 승인·판단 단계는 둥근 테두리와 `HUMAN DECISION` 라벨로
표시한다. 가장 강한 강조색은 AI가 아니라 사람 승인에 쓴다.

### 한계를 본문에 두기

한계와 미반영은 아코디언 속에 숨기지 않는다. 결과 카드와 같은 크기·계층으로 배치한다.

## 4. 디자인 토큰

### 색

| 용도 | 값 | 설명 |
|---|---:|---|
| Paper | `#F3F0E8` | 전체 배경, 따뜻한 연구 문서 |
| Paper Light | `#FBFAF6` | 카드·본문 |
| Ink | `#173B36` | 제목·주요 텍스트, 짙은 청록 |
| Ink Soft | `#49635F` | 보조 텍스트 |
| Line | `#C9CEC6` | 구분선·격자 |
| Signal | `#D9563F` | 사람 승인·판단 지점 전용 |
| Signal Dark | `#A83929` | Signal 호버·고대비 |
| Field | `#DDE7C7` | 구현됨·검증된 실행 경로 |
| Planned | `#F3D6A3` | 예정·준비 중 |
| Synthetic | `#D9D6EA` | 가상 시민 검증 전용 |
| Error | `#A12C2C` | 경고·실패 |

본문 `Ink`/`Paper`와 일반 버튼 `Paper Light`/`Ink` 조합은 WCAG AA 이상을 목표로 실제 검사한다.
주홍 Signal은 사람 승인·판단 표시에만 쓰고 일반 CTA와 공유하지 않는다.
상태 배지는 색과 텍스트를 함께 쓴다.

### 타이포그래피

- 외부 웹폰트 없음.
- 제목: `ui-serif, Georgia, "Noto Serif KR", "Batang", serif`
- 본문: `system-ui, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- 기본 본문: 18px / 1.72
- 작은 보조문: 최소 14px / 1.55
- 표지 제목: `clamp(2.65rem, 7vw, 6.6rem)`, 글자 간격 `-0.045em`
- 본문 행 길이: 최대 68자 안팎

한국어 제목에서 serif 글꼴이 없으면 시스템 sans로 안전하게 대체된다. 특정 OS 글꼴에 레이아웃이
의존하지 않도록 한다.

### 간격·크기

- 콘텐츠 최대 폭: 1200px
- 읽기 본문 최대 폭: 760px
- 페이지 좌우 여백: `clamp(20px, 5vw, 72px)`
- 섹션 상하: 데스크톱 120px, 모바일 72px
- 카드 모서리: 2px 또는 18px 두 종류만 사용
- 모든 링크·버튼 터치 영역: 최소 44×44px

## 5. 공통 구조

### 접근성 시작점

- 문서 첫 요소: `본문으로 건너뛰기`
- `header/nav/main/footer` 의미 구조
- 페이지마다 `h1` 하나, 제목 단계 건너뛰기 금지
- 현재 메뉴 `aria-current="page"`
- 모바일 메뉴는 실제 `button`, `aria-expanded`, Escape 닫기, 포커스 복귀
- 모바일 메뉴가 열리면 메뉴 안에 포커스를 가두고 본문 스크롤을 막음
- `prefers-reduced-motion: reduce`에서 전환·스크롤 애니메이션 제거
- `prefers-contrast: more`에서 구분선과 포커스 표시 강화
- 200% 확대 및 360px에서 가로 스크롤 금지

### 헤더

```text
[POLICY LAB / OPEN SOURCE]   프로젝트  작동 방식  플랫폼  실증 사례  신뢰 원칙  오픈소스   [GitHub ↗]
```

- 높이 76px, 종이색 반투명 배경과 1px 하단선
- 데스크톱은 상단 고정, 모바일은 로고 + 메뉴 버튼
- 공식 기관 로고는 사용하지 않음

### 상태 띠

헤더 아래 짧은 상태 문장:

전역에는 `SOFT LAUNCH · 검색 비노출`만 표시한다.

`FIRST FIELD CASE · 2026.08.12 예정`은 홈의 사례 섹션과 연금 사례 상세에만 표시한다. 모든 페이지에
행사 상태를 반복해 프로젝트 전체가 연금 행사 사이트로 보이게 하지 않는다.

### 푸터

- 한 문장 정의
- 사이트맵
- GitHub, Apache-2.0, 상태, 보안 제보
- 역할 고지: Nextain 공개 저장소 / 한국정책학회 첫 현장 실증
- “AI는 정책을 결정하지 않습니다. 사람의 판단을 지원하고 과정을 기록합니다.”
- 검색 비노출 소프트 공개 상태와 최종 갱신일

## 6. 핵심 컴포넌트

### 6.1 결정 경로(Decision Trail)

여섯 단계를 가로선 위 카드로 표현한다. 모바일에서는 세로 흐름으로 바뀐다.

```text
문제·근거 ─ 전문가 대안 ─ 청중 의견 ─ AI 교차검토 ─ [사람 승인] ─ 재수렴·공개
```

- 각 카드에 `입력 / AI 역할 / 사람 권한 / 남는 기록` 중 필요한 항목 표시
- 사람 승인만 주홍 테두리
- 번호보다 단계 이름을 먼저 읽게 함

### 6.2 관점 카드(Perspective Sheet)

연구자·공공기관·시민사회·개발자 진입점을 문서 탭처럼 겹쳐 놓은 카드. 호버 없이도 모든 정보가
보인다.

### 6.3 상태 배지

- `구현됨` — 초록빛 Field
- `설계 원칙` — 무채색 아웃라인
- `2026.08.12 예정` — Planned
- `가상 시민 검증` — Synthetic
- `후속 과제` — 점선 아웃라인

### 6.4 검토 쌍(Kept / Left Open)

`반영한 것`과 `남은 한계`를 같은 폭으로 나란히 배치한다. 모바일에서도 순서상 결과 다음에 한계가
바로 이어지며 접히지 않는다.

### 6.5 출처 링크(Source Note)

핵심 주장 아래 작은 번호와 `코드`, `RFC`, `실험 보고서`, `행사 안내` 유형을 표시한다. 새 탭 아이콘과
스크린리더용 대체문구를 둔다.

### 6.6 실증 사례 카드

연금 결과 차트가 아니라 다음 네 정보를 우선한다.

1. `Reference Case 01`
2. 실증 질문
3. 상태 `첫 현장 실증 예정`
4. 일정·장소·참여 구조

가상 시민 보고서 링크는 별도 보라색 영역에 `사전 엔진 검증 · 실제 여론 아님`을 먼저 표시한다.

## 7. 페이지 와이어프레임

### 홈

```text
┌ 상태 띠 ──────────────────────────────────────────────┐
│ OPEN SOURCE POLICY DECISION SUPPORT                   │
│ 정책결정의 더 나은 과정을,                            │
│ 사람과 AI가 함께 만듭니다.               [결정 경로]  │
│ 설명 + [프로젝트 보기] [GitHub]                       │
├ AI가 결정하지 않습니다 ───────────────────────────────┤
│ 왜 필요한가 / 세 원칙                                 │
│ 6단계 결정 경로                                       │
│ 첫 실증 사례(예정)                                    │
│ 누구를 위한 프로젝트인가                              │
│ 오픈소스 구조 + 현재 상태                             │
└ footer ───────────────────────────────────────────────┘
```

표지 오른쪽 시각물은 사람·AI·근거·한계를 연결한 CSS 선과 텍스트 노드다. 장식용 로봇·두뇌 이미지는
사용하지 않는다.

### 프로젝트

- 큰 질문: “정책 난제에서 더 필요한 것은 더 빠른 답인가, 더 검토 가능한 과정인가?”
- 하는 일 / 하지 않는 일 2열
- 네 역할과 결정권 경계
- 범용 구조와 첫 실증 관계
- 운영·협력 역할 고지

### 작동 방식

- 6단계 세로/가로 결정 경로
- 각 단계의 입력·출력·사람 게이트
- 기록되는 provenance 항목
- 원칙과 구현 상태 구분

### 플랫폼

- 세 표면: 시민 화면 / 진행자 작업공간 / 연구 엔진
- 실제 UI를 과장된 기기 목업 대신 구조화된 CSS 패널로 재현
- 구현됨 / 온라인 운영 준비 중 구분
- 정적 공개 사이트와 동적 행사 서비스 경계도

### 실증 사례 목록

- “정책 분야가 아니라 검증 질문으로 분류한다”는 소개
- Reference Case 01 카드
- 다음 사례 자리표시자는 만들지 않는다. 실제 사례가 생길 때 추가한다.

### 연금 실증 상세

- 행사 전 상태와 일정
- 실증 연구 질문
- 정책연구팀·AI팀·좌장
- 현장 6단계
- 사전 가상 시민 엔진 검증(별도 색·경고)
- 행사 후 공개할 항목 체크리스트

### 신뢰 원칙

- 방어장치 6개를 “막는 위험 / 강제 위치 / 현재 상태”로 제시
- AI가 할 수 없는 것
- 알려진 한계
- 원문 RFC·코드 링크

### 오픈소스

- 저장소 구조 시각화
- 5분 시작 명령
- 기여 경로
- 라이선스·보안·행동강령

### 상태

- 마지막 갱신일
- 구현됨 / 첫 실증 예정 / 후속 과제 3열
- 배포 상태와 검색 비노출
- 행사 전·후 게시 체크리스트

## 8. 반응형 동작

### 360–767px

- 단일 열
- 표지 제목 최대 3.5rem
- 결정 경로 세로
- 표·코드가 필요한 경우 자체 가로 스크롤 컨테이너, 페이지 전체는 고정
- 모바일 메뉴 오버레이가 아니라 헤더 아래 종이 패널
- 카드 내부 패딩 20px

### 768–1023px

- 2열 카드
- 표지 5:4 비율
- 결정 경로 3×2

### 1024px 이상

- 12열 그리드
- 표지 텍스트 7열 / 결정 경로 시각 5열
- 본문과 주석을 8열 / 3열로 분리
- 실증 상세의 사실표는 우측 고정이 아닌 일반 흐름으로 유지

## 9. 상호작용과 모션

- JS는 모바일 메뉴, 현재 연도, 선택적 복사 버튼에만 사용
- 필수 콘텐츠는 JS 없이 모두 읽힘
- 등장 애니메이션 없음
- 링크·버튼 호버는 색·밑줄·1px 이동만, 160ms 이하
- 부드러운 스크롤은 모션 감소 설정에서 비활성
- 자동 재생, 캐러셀, 카운트다운 없음
- 인쇄 시 내비게이션·버튼을 숨기고 URL·출처·한계 본문은 유지

## 10. 검색 비노출과 프라이버시의 시각화

- 소프트 공개 상태는 `/status/`와 푸터에만 조용히 표시하고 표지의 주 메시지를 방해하지 않는다.
- 쿠키 배너가 없는 이유는 쿠키·분석기가 없기 때문이다.
- 외부 자원은 GitHub와 현재 정적 보고서 링크뿐이며 폰트·이미지·스크립트를 불러오지 않는다.
- `noindex`는 화면 보안이 아님을 `site/README.md`에 기록한다.

## 11. 디자인 완료 기준

- D-01 표지만 보고 연금 사이트가 아니라 범용 오픈소스 프로젝트로 읽힌다.
- D-02 AI보다 사람 승인 요소가 시각적으로 더 강하다.
- D-03 가상 검증과 실제 현장 예정이 색 없이도 텍스트로 구분된다.
- D-04 구현·원칙·예정·후속 상태가 모든 관련 카드에 표시된다.
- D-05 모든 페이지가 하나의 `h1`, 건너뛰기 링크, 의미 구조를 가진다.
- D-06 360px·200% 확대에서 페이지 가로 스크롤이 없다.
- D-07 색 대비·포커스·44px 터치 목표를 검사로 확인한다.
- D-08 외부 폰트·이미지·분석기·쿠키가 없다.
- D-09 행사·팀 정보가 프로젝트 정체성을 덮지 않고 사례 상세 안에 머문다.
- D-10 한국정책학회 공식 사이트로 오인시키는 로고·표현이 없다.
- D-11 일반 CTA와 사람 승인 표시가 색·라벨로 구분된다.
- D-12 전역에는 프로젝트 상태만, 연금 행사 상태는 홈 사례·상세 페이지에만 나타난다.
