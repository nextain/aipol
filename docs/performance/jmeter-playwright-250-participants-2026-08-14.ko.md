# AIPOL 250명 전 과정 성능 실측 보고서

2026년 8월 14일, AIPOL 연금정책실험 공개 서비스에 대해 JMeter 250세션과 실제 Chromium 브라우저 250개를 사용해 외부 부하 실측을 진행했다. 기존의 1차 투표 중심 측정은 이번 **10단계 최종 결과보고 완주 측정**으로 대체한다.

## 비개발자를 위한 한눈 요약

이번 실측에서는 외부 Azure VM 세 대에서 서로 독립된 Chromium 250개를 실제로 열었다. 각 브라우저가 참가자 화면에서 정책안을 읽고 버튼을 클릭하고 이유를 입력해 1·2·3차 응답을 저장한 뒤, 최종 결과보고까지 열었다.

| 확인 항목 | 결과 |
|---|---:|
| 10단계 전 과정 완주 | **250/250** |
| 1·2·3차 응답 저장 | **각 250명, 총 750회** |
| 최종 결과보고 열기 | **250/250, HTTP 200** |

현재 구성은 이번 시험 조건에서 250명의 동시 행사 전 과정을 정상 처리했다. 다만 실제 사람 250명을 모집한 조사가 아니라 비식별 합성 프로필을 사용한 서비스 시험이다. 아래 숫자로 정책 선호나 숙의 효과를 해석해서는 안 된다.

## 시험 구성

- **JMeter 250세션**은 8,000건의 HTTP 요청으로 서버와 API 처리량을 측정했다.
- **Playwright + Chromium 250개**는 프로필마다 독립 `chromium.launch()`를 실행해 실제 JavaScript 화면과 버튼 조작을 검증했다.

Chromium 부하 발생기는 Korea Central의 `Standard_D16as_v5` 세 대였다. 84개, 83개, 83개 브라우저로 나눠 총 48 vCPU·192GB를 사용했다. 모든 요청은 공개 DNS·TLS·nginx·Node(vinext)·PostgreSQL 경로를 거쳤다. 시험 뒤 임시 VM 리소스 그룹은 삭제했다.

## 한 번에 5대 쟁점 전체 분류

1차 투표 이유 750건은 관리자가 `남은 전체 한 번에 분류` 버튼을 한 번 클릭해 처리했다. 브라우저가 내부적으로 75건씩 10개 안전 배치를 연속 호출했고, `분류 750건·남음 0건`을 확인했다. 관리자 화면의 HTTP·콘솔 오류도 0건이었다.

## 함께 해소한 공개 UI 자산 결함

이전 부분 실측에서 `/aipol-logo.png/`가 404를 반환한 문제는 로고 경로와 자산 처리 방식을 수정해 해결했다. 관리자 JavaScript의 CSS 전용 보조 청크가 빌드에서 누락되는 문제도 발견해, 배포 전에 매니페스트가 참조하는 모든 자산의 실제 존재를 검사하도록 게이트를 강화했다.

운영 커밋 `eef1d43` 배포 후 외부 Chrome smoke와 이번 Chromium 250개 전 과정 실측에서 자산·콘솔 오류는 모두 0건이었다.

- 실제 사람, 실제 통신사망, 다양한 휴대전화와 보조기기 사용을 모두 재현한 시험은 아니다.
