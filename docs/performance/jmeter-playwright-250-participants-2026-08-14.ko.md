# 250명 동시 참여: JMeter + 실제 Chromium 성능시험

2026년 8월 14일, AIPOL 연금정책실험 공개 참가 경로를 JMeter 250세션과 Playwright Chromium 250개로 각각 시험했다.

## 비개발자를 위한 한눈 요약

### 무엇을 확인했나

- **JMeter**는 브라우저가 아니다. 250개의 가상사용자 세션으로 서버에 접속·상태확인·투표 요청 8,000건을 보내 처리 능력을 측정했다.
- **Playwright Chromium**은 실제 브라우저 엔진이다. 독립 Chromium 250개가 참가자 화면을 열고 정보를 입력한 뒤 정책안을 선택하고 `응답 저장` 버튼을 눌렀다.

### 결론

| 질문 | 결과 |
|---|---:|
| 실제 Chromium 화면 진입 | 250/250 성공 |
| 실제 화면 투표 저장 | 250/250 성공 |
| Chromium 실패 여정·요청 실패 | 0건 · 0건 |
| Chromium 화면 진입 | p95 84ms |
| Chromium 투표 저장 | p95 113ms |
| JMeter 전체 요청 | 8,000/8,000 성공 |
| JMeter 전체 응답 | p95 20ms |
| 운영 DB 확인 | 고유 참여자 250명 · 1차 투표자 250명 |
| 서비스 안정성 | 앱 재시작 0회 · 서버 오류 로그 0건 |
| 측정 당시 로고 404 | 2026-08-14 수정·재배포 후 외부 Chromium 검증 완료 |

정의한 250명 접속·폴링·투표 시나리오를 안정적으로 처리했다. 다만 합성 프로파일의 A/B/C 선택은 부하 입력일 뿐 국민 여론이나 정책효과가 아니다.

## 시험 구조

```text
Azure JMeter 2대 · 가상사용자 250세션 ─┐
                                        ├─ 공개 인터넷/DNS/TLS ─ nginx ─ Node ─ PostgreSQL
Azure Playwright 3대 · Chromium 250개 ──┘
```

두 시험 모두 운영 서버 내부가 아닌 별도 Azure VM에서 `https://session.aipol.kaps.or.kr` 공개 도메인으로 접속했다. 모든 참가자는 서로 다른 비식별 합성 프로파일과 이벤트별 토큰을 사용했다.

## 실제 Chromium 250개 시험

프로파일마다 Playwright의 `chromium.launch()`를 별도로 호출했다. 하나의 브라우저에서 탭이나 context만 250개 만든 시험이 아니다. 3대의 `Standard_D16as_v5` VM에 84/83/83개로 분산했다.

각 브라우저는 다음 흐름을 수행했다.

1. 공개 참가자 URL 접속과 JavaScript 렌더링
2. 익명 프로파일 적용
3. A/B/C 합성 선택 클릭
4. 수용 수준과 선택·비선택 이유 입력
5. 실제 `응답 저장` 버튼 클릭과 저장 완료 확인
6. 총 5분 동안 화면을 유지하며 10초 이벤트 폴링

| 지표 | 실측 |
|---|---:|
| 독립 Chromium 실행/정상 종료 | 250/250 · 250/250 |
| 화면+투표 전체 여정 | 250/250 |
| 화면 진입 | p50 47ms · p95 84ms · p99 276ms · 최대 354ms |
| 투표 저장 | p50 85ms · p95 113ms · p99 154ms · 최대 218ms |
| 요청 실패 | 0 |
| 앱 VM CPU | 평균 3.12% · 최대 9.12% |
| PostgreSQL CPU | 평균 12.37% · 최대 17.69% |
| PostgreSQL 활성 연결 | 평균 10.94 · 최대 14 |

브라우저 실행기 3대의 평균 CPU는 2.72~2.89%, 평균 메모리는 8.41~8.58%였다. 실행기 자체 병목 징후는 없었다.

## JMeter 250세션 시험

JMeter 세션마다 참가자 페이지 1회, 이벤트 상태 10초 폴링 30회, 1차 투표 1회를 수행했다.

| 지표 | 실측 |
|---|---:|
| 전체 요청 | 8,000/8,000 성공(100%) |
| 전체 응답 | p50 10ms · p95 20ms · p99 46ms · 최대 241ms |
| 페이지 진입 | 250/250, p95 20ms |
| 상태 폴링 | 7,500/7,500, p95 15ms |
| 1차 투표 저장 | 250/250, p95 56ms |
| 앱 VM CPU | 평균 1.96% · 최대 3.72% |
| PostgreSQL CPU | 평균 20.76% · 1분 최대 84.61% |

사전 기준인 성공률 99.5% 이상, p95 2초 미만, 투표 250/250을 모두 충족했다.

## 발견한 UI 결함과 후속 조치

측정 당시 Chromium 250개 모두 핵심 여정에 성공했지만 `/aipol-logo.png/`가 브라우저마다 두 번씩 404를 반환했다. HTTP·콘솔 오류는 각각 500건이며 URL은 전부 동일했다. 참가자 API나 투표 저장 성능에는 영향을 주지 않았지만 공개 UI 품질 결함으로 분류했다.

2026년 8월 14일, 기존 AIPOL의 시민·궤도·별 상징을 응용한 새 헤더 로고와 글자를 제외한 상징 전용 파비콘을 적용했다. 로고를 브라우저가 별도 HTTP 파일로 요청하지 않는 최적화된 자산으로 제공해 주소 끝에 불필요한 `/`가 붙는 요청 자체를 제거했다. 재배포 후 외부 Chromium으로 참가자·관리자·결과 화면을 다시 확인한 결과 로고 관련 HTTP·콘솔 오류는 0건이었고 참가자 화면과 참가자 API는 모두 HTTP 200이었다.

이 후속 검사에서 관리자 전용 JavaScript 파일 404 한 건을 별도로 발견했다. 250명 참가자 여정과 로고 수정에는 영향을 주지 않으며, 공개 참가 화면 결함과 분리해 운영 UI 후속 항목으로 관리한다.

## “250명”의 의미와 한계

- 실제 사람 250명을 모집한 사용성·정책조사가 아니라 비식별 합성 프로파일 250개로 수행한 웹서비스 성능시험이다.
- Chromium은 실제 브라우저 엔진과 UI를 사용했지만 사람의 읽기·망설임, 기기 다양성, 가정망 품질까지 재현하지 않는다.
- 최대 처리량이나 장애 시작점을 찾는 파괴시험은 하지 않았다.
- 1차 투표까지 측정했고 AI 숙의·분류·외부 모델 호출은 제외했다.
- 단일 유효 실행씩의 결과이므로 중요한 행사 전에는 같은 게이트를 재실행하는 것이 안전하다.

## 데이터·보안 경계

시험마다 전용 이벤트를 만들고 DB에서 고유 참여자 250명과 1차 투표자 250명을 확인한 뒤 시험 이벤트와 종속 데이터를 삭제했다. 임시 Azure 부하발생기 자원도 제거했다.

원시 JTL, 브라우저별 상세 결과, 참여자 토큰, 운영 IP와 내부 DB 자료는 비공개 운영 저장소에만 둔다. 이 공개 보고서에는 재현에 필요한 방법과 비식별 집계만 포함한다.
